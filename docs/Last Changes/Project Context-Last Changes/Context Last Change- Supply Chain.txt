1. Blueprint Organisation – Supply Chain Module

text

CRITICAL: Folder name must be supply_chain (underscore). URL prefix is /supply-chain (hyphen). Python module names cannot contain hyphens.

Registration in app/__init__.py (use unique alias to avoid blueprint name clash):

python
from app.modules.supply_chain import supply_chain_bp, api_bp as supply_chain_api_bp
app.register_blueprint(supply_chain_bp)
app.register_blueprint(supply_chain_api_bp)
Lesson learned: All API blueprints must use unique import aliases (project_api_bp, engineering_api_bp, admin_api_bp, manufacturing_api_bp, supply_chain_api_bp) because each module names its variable api_bp. Also: internal blueprint names must be unique (Blueprint('supply_chain_api', ...) — not 'api').

6. Frontend Conventions (Supply Chain)
All pages extend base.html, use Bootstrap 5 + jQuery (local).

Layout pattern: Filters row → KPI cards row → Main card with table + action buttons → Modals.

KPI colours: primary (neutral), info (in progress), warning (partial), success (closed), danger (overdue).

Date handling: filter inputs are HTML date (YYYY-MM-DD); convert to INT key before sending (parseInt(date.replace(/-/g,''))).

URL parameter pre-filtering: pages read query params (e.g., ?product_id=X) via URLSearchParams, pre-fill the filter input, then auto-refresh.

Live filtering: bind input (text) and change (date/select) events to the load function instead of relying only on a Refresh button.

Dropdowns: /api/products/list and /api/warehouses/list return [{id, name/desc}].

CSV export: window.location.href = '/api/.../export?' + params (server builds CSV with StringIO + csv.writer).

7. Business Logic Lessons
PO receiving: update t_PurchaseOrderDetail.ReceivedQuantity per line, insert into t_InventoryTransactions (type Purchase Receipt, positive Qty), then re-evaluate PO header status (Draft → Sent → Partially Received → Closed). Optional flag creates t_QualityInspectionBatch row (Status Pending, DueDateKey = today+7).

Stock adjustment: positive → insert or increase t_InventoryOnHand row; negative → decrease or delete. Always create t_InventoryTransactions entry with type Adjustment.

Stock transfer: decrease source warehouse, increase destination, record single Transfer transaction (FromWarehouseID/ToWarehouseID).

Shipment creation: validates against t_SalesOrderLine.Quantity minus shipped; updates ShippedQuantity; creates negative Sales Issue inventory transaction; sets SO status to Shipped when fully shipped.

Valuation methods: weighted_avg uses AVG(UnitCost) per product+warehouse; standard uses t_Product.StandardCost. Total value = Σ(Qty × cost).

Warehouse utilisation: Σ(Qty from t_InventoryOnHand where WarehouseID) / t_Warehouses.Capacity × 100.

Supplier portal users: insert into t_Users with UserType='External', PortalAccess=1, CompanyID=<SupplierID>. Store hashed password in PasswordHash (column added via migration).

Audit logging: helper log_audit(action, table, record_id, old, new, user_id) writes into t_AuditLog with DateKey = today_key().
