#### 7.7.5 Why not auto.HASH? (v47 — STRICTLY DEPRECATED)

Auto.HASH keys (auto.xxxxxxxx) are produced by the translation sync 
tool when it scans unwrapped English strings. They pollute the DB, 
break convention, and make it impossible to reason about which 
module owns a key.

**Rule (v47)**: NEVER write new code that inserts auto.HASH keys. 
NEVER accept auto.HASH keys in new page configs. If they already 
exist in t_Translations, they are considered legacy and may be 
deleted once their page has been migrated to semantic keys.

#### 7.7.5.1 Mandatory Key Conventions (v47)

  global.*            → reusable (Save, Cancel, Actions, Status, Loading, …)
  <module>.*          → module-level pages, e.g. crm.dashboard.*
  <module>.<page>.*   → page-specific, e.g. manufacturing.job_orders.*
  <module>.<page>.kpi.*       → KPI card labels
  <module>.<page>.table.*     → table column headers
  <module>.<page>.filters.*   → filter labels
  <module>.<page>.form.*      → modal form labels
  <module>.<page>.action.*    → action buttons
  <module>.<page>.modal.*     → modal titles
  <module>.<page>.msg.*       → toast / empty-state messages
  <module>.<page>.<entity>.*  → entity-specific (e.g. motor.assembly.*)

#### 7.7.5.2 No Numbers in Semantic Keys (v47)

Wrong:  motor.part01.name, line.1.label
Right:  motor.rotor.name,  motor.line_casting.label

Numbers in keys make renaming and searching painful. Use words.

#### 8.20.6 Batch / Lot NVARCHAR Patterns (v47)

All batch/lot quantities (BatchQuantity, GoodQuantity, ScrapQuantity, 
YieldPercent, InputQuantity, OutputQuantity) are NVARCHAR in the 
current SQL Server schema. Rules:

**SQL**: always CAST to DECIMAL(18,4) before arithmetic:
  CAST(GoodQuantity  AS DECIMAL(18,4)) 
  CAST(ScrapQuantity AS DECIMAL(18,4))

**Python**: always safe_float() before comparison:
  yield_pct = safe_float(row[6])
  if yield_pct < 95.0:  # flag low yield
      ...

**Boolean lot flags** (IsBatchTracked, IsLotTracked, Backflush):
  SQL:    WHERE IsBatchTracked = '1'
  Python: if is_active_true(row[12]): ...

**Yield calculation** (safe pattern):
  good   = safe_float(row_good)
  input_ = safe_float(row_input)
  yield_ = round(good / input_ * 100, 2) if input_ > 0 else 0.0

20. MTS BATCH / LOT MANUFACTURING MODEL (v47)

### 20.1 Why Batch/Lot Matters

In MTS (Make to Stock) industries — motors, pumps, castings, paint, 
electronics — production happens in BATCHES at each workstation, not 
one unit at a time. A 500-unit order may pass through:

  10 Casting        → 500 in  → 495 out   (5 scrap)
  20 Machining      → 495 in  → 490 out   (3 scrap, 2 rework)
  30 Winding (sub)  → 490 in  → 487 out
  40 Assembly       → 487 in  → 485 out
  50 Testing        → 485 in  → 480 pass, 5 fail → NCR
  60 Packing        → 480 in  → 480 ready

### 20.2 Definitions

BATCH  = one production run of a specific operation 
         (all items made in one setup on one machine)
LOT    = one traceable quantity of material at a specific stage
         (may split from a batch, or join a shipment)

Relationship: 1 Batch → N Lots. Each Lot has a ParentLotID chain.

### 20.3 Database Model

t_ProductionOrder
  + BatchNumber, LotNumber, ParentBatchID, GoodQuantity,
    ScrapQuantity, YieldPercent

t_ProductionOrderDetail (1 row per operation per order)
  + InputQuantity, OutputQuantity, ScrapQuantity, LotID,
    OperatorID, MachineID

t_Lot (NEW)
  LotID (PK), ProductionOrderID, BatchNumber, ParentLotID,
  ProductID, Quantity, GoodQuantity, ScrapQuantity,
  CurrentStation, Status, CustomerID,
  CreatedDateKey, ClosedDateKey, DemoIndustryCode

t_ScrapReason (NEW)
  ScrapReasonID (PK), Code, Name, NameLocal, Category,
  IsActive, DemoIndustryCode

t_ShopFloorTransactions
  + LotID, BatchNumber, InputQty, OutputQty, ScrapQty, ScrapReason

t_Product
  + Backflush, IsBatchTracked, IsLotTracked, DefaultBatchSize

t_InventoryOnHand / t_InventoryTransactions
  + LotID (nullable)

### 20.4 Operator-Facing Model (Two Layers)

LAYER 1 — Operator sees physical lots (barcode / traveler card).
          Reports: Lot, Station, Good Qty, Scrap Qty, Machine.
          Total time: 10 seconds per operation.

LAYER 2 — System resolves to Job Order via LotID lookup.
          Updates t_ProductionOrderDetail, triggers backflush,
          rolls up yield to t_ProductionOrder.

### 20.5 Backflushing vs MRP (do not confuse)

MRP           → BEFORE production. "How much do I need?"
Backflushing  → AFTER production.  "What did I consume?"

Both use the BOM. Both write to t_Inventory*.
MRP plans. Backflush records.

### 20.6 Yield Formula

  InputQuantity  = previous operation's OutputQuantity
  OutputQuantity = good pieces at this operation
  YieldPercent   = Output / Input × 100
  ScrapQuantity  = Input - Output - ReworkQuantity

### 20.7 Workstation Reporting Rules

Rule 1: Input for station N = Output of station N-1 (chain integrity)
Rule 2: Every operation creates a t_ProductionOrderDetail row
Rule 3: Scrap always requires a reason code from t_ScrapReason
Rule 4: Rework is a distinct status, not counted as scrap
Rule 5: Yield < threshold → flag for QC Manager review

21. SIXTH DEMO INDUSTRY — MOTOR MTS (v47)

### 21.1 Overview

Industry Code: motor

Company:       Pars Electric Motors Co.

Demonstrates:
  - Mass-production batch/lot flow
  - Per-station reporting

  - NCR + CAPA triggered by testing failure

  Seq 10  Casting         WC-CASTING    1 setup + 0.05 hrs/unit
