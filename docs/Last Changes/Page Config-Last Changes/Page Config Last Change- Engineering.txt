B3. Routings & Work Instructions — Four Tabs (2026‑09‑16)
Page: /engineering/routings

KPI Cards: Total Routings, Active Routings, Inactive Routings.

Tabs:

Table View — classic row‑based routing list with Edit / Delete / View Work Instructions.

Gantt View — sequential vs parallel timeline. Parallel operations share the same OperationSequence. Read‑only. Displays S/R/Q/M breakdown below each bar.

Process Flow — multi‑product horizontal flow showing which products share each work center. Responsive (horizontal on desktop, vertical on mobile).

Join Map — component join map showing which components meet at each workstation, with a color‑coded join type (Weld / Bolt / Press / Glue / Screw / None). Interactive — clicking a node opens a detail modal.

Data sources: t_WorkCenterRouting, t_WorkCenter, t_Product, t_BOM, t_WorkInstructions.

SQL Server notes: All queries include every non‑aggregated column in GROUP BY. Dates passed as string parameters.

B4. Engineering Documents — DMS Page (2026‑09‑16)
Page: /engineering/documents

KPI Cards: Draft, Under Review, Approved, Obsolete, Checked Out.

Table columns: Doc Number (link), Title, Rev, Status, Checked Out By, Checked Out Date, Last Modified, Actions.

Modals:

Upload / New Revision

Check Out

Check In (optional new revision file)

Share Externally

Preview (iframe)

Actions per row: Preview, Check Out, Check In, Share.

Data sources: t_EngineeringDocument (+ t_DocumentRevisions for future history).

Document storage strategy:

Generated HTML: static/documents/generated/engineering/<PROJECT_ID>/<DOC>-Rev<N>.html — bilingual, print‑ready, self‑contained.

Uploaded (legacy) files: static/uploads/ (or static/uploads/legacy/) — one language per file.

API endpoints:

GET /api/bom/documents — list with filters (doc_type, status, checkout_status, project)

GET /api/bom/documents/<string:doc_id> — detail

POST /api/bom/documents/<string:doc_id>/checkout

POST /api/bom/documents/<string:doc_id>/checkin

POST /api/bom/documents/<string:doc_id>/share

GET /api/bom/documents/stats

Critical: DocumentID is a string (nvarchar). All routes use <string:doc_id>, not <int:doc_id>.

B7. Lessons Learned — Engineering Page‑Specific
Route routings must pass both products (for Gantt/Flow/Join Map product dropdowns) and work_centers (for the Add/Edit routing modal).

Route eco must pass both products (affected product filter) and projects (project filter).

Route bom calls get_products_for_selector(request) — must receive the request object.

Do not duplicate routes in __init__.py. The package initializer should only re‑export engineering_bp.

DocumentID is a string — all document routes and JS must treat it as a string.

HTML documents are previewed in an iframe — the FilePath must include the static/ prefix so the URL resolves.

Generated HTML files do not need a shared JS library — each file carries its own bilingual toggle.
