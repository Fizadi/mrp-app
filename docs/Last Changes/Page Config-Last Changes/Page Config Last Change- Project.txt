Sidebar Project Selector Behavior (v42)

The sidebar project selector (in sidebar.html) is implemented in pure
JavaScript (see PROJECT CONTEXT Section 7.9). When the user selects a
project:

- A POST is sent to /api/set-current-project with {project_id: "..."}
- The server stores session['current_project_id']
- The page reloads with cache-busting (?t=timestamp)
- Every subsequent API call reads session['current_project_id']
- Pages that use project filtering (BOM, MS Project, deliverables, etc.)
  filter their data accordingly

The MS Project Integration index route reads session['current_project_id']:

- If "All" → redirects to /project/project_portfolio
- Otherwise → redirects to /project/ms-project-integration/<project_id>

This is defined in app/modules/project/routes.py.

Known Issues Fixed During This Module's Development (v42)

1.  Type mismatch in get_schedule_tasks (r[6] > 0 on nvarchar)
    → Fixed with CAST(PlannedPercent AS DECIMAL(18,4)) + float() in Python.

2.  ISNULL(SUM(AllocationPercent), 0) failed on nvarchar
    → Fixed with SUM(CAST(AllocationPercent AS DECIMAL(18,4))).

3.  IsActive = 1 silently failed on nvarchar columns
    → Fixed with IsActive = '1' (string literal).

4.  bool(row[i]) returned True for '0' values
    → Replaced with is_active_true(row[i]) helper.

5.  Duplicate /api/set-current-project route (in core/routes.py AND
    init.py) caused nondeterministic behavior
    → Kept only the core/routes.py version.

6.  Sidebar project selector used jQuery delegated handler
    → Rewritten in pure JS (see PROJECT CONTEXT Section 7.9).

7.  Language switching broken on customer_projects_list.html
    → Root cause: duplicate jQuery load in {% block scripts %}.
    Fixed by removing the duplicate.

8.  Project portfolio table empty even though API returned data
    → Root cause: same duplicate jQuery load breaking the ready queue.
    Fixed by rewriting the page with the standard pattern.

9.  LLM-invented translation values broke engineering BOM page
    → Rolled back using backup table. See PROJECT CONTEXT Section 8.23.

10. The auto.* hash key audit showed ~1,600 spurious keys
    → Filtered out; only ~270 real semantic keys needed insertion.
